# 房颤预警复核服务

腕戴设备一夜可产生几十条疑似房颤提示，其中运动伪迹与真实发作混杂。本服务保存 PPG 摘要与按需单导联 ECG，
把相邻 / 重叠提示合并为**可解释的发作候选**，供随访护士分流，而不是把设备算法判断直接当成诊断。

设备时间、时区、固件、算法版本、校准版本属于原始采集上下文，全链路保留。

## 运行

```bash
npm install
npm test        # tsc 严格类型检查 + fixtures/night-events.json 回放自检
npm run replay  # 仅回放（打印候选、风险依据、队列、时间线、审计）
```

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/contracts.ts` | 领域契约：上传信封、信号片段、发作候选、质量依据、风险评估、复核、授权、审计 |
| `src/time.ts` | 采集时间必须带 UTC 偏移；比较走 UTC 毫秒轴；本地日期按时区渲染用于跨午夜归属 |
| `src/ingest.ts` | 信封校验、设备上下文盖章、按 `packetId` 幂等去重（批内 / 跨批重传 / 冲突载荷区分） |
| `src/episodes.ts` | 仅 PPG 提示参与聚类；相邻（≤120s）或重叠合并；ECG 作为核对证据挂载；松动 / 运动 / 缺口列为质量依据；风险逐条加减分 |
| `src/service.ts` | 护士（标记伪迹 / 联系 / 升级）、医生（仅追加更正）状态机，待联系队列，时间线，授权门控，只增审计 |
| `src/replay.ts` | 样例回放与 40+ 项断言 |

## 关键边界

- **算法不等于诊断**：风险分层只产生 `screening / watch / urgent` 与可枚举加减分理由；诊断性结论只能由医生
  以 `disposition: "correct"` 追加（`correctsReviewId` 指向被更正记录），历史记录不覆盖、不删除。
- **幂等摄入**：重复 `packetId` 且载荷一致 → 记审计、不产生新窗口；载荷冲突 → 拒绝并单列，绝不静默覆盖。
- **联系闭环**：未触达不允许闭环；未闭环发作停留在「联系进行中」队列。
- **授权撤回**：患者撤回后，护士 / 医生对该患者的列表、波形读取与处置全部拒绝（拒绝留痕）；
  审计角色仍可读取状态时间线，审计日志无删除接口。
- **跨午夜**：`localStartDate / localEndDate` 按设备时区给出日历日期归属，`crossedMidnight` 显式标注。
